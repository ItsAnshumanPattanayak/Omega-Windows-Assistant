# Omega 2.0.0 upgrade notes

Status: **Unreleased source implementation**. No `v2.0.0` tag, GitHub Release,
installer publication, or documentation-site publication is implied by this page.

## Experience changes

- Exact registered application names and aliases now produce a context-bound question
  before opening. `Notepad`, `note pad`, `Calculator`, `Chrome`, `Settings`,
  `Visual Studio Code`, `vs code`, and `File Explorer` resolve through the reviewed
  application registry.
- The conversation is the dominant GUI area. User and Omega messages have distinct
  alignment, recent activity can collapse, and all Version 1 secondary actions are
  grouped under **More Activities**.
- Voice startup reports bounded model, microphone, sample-rate, and recognizer state.
  Configured microphone indices and exact names are validated before listening.
- The default offline model is the official 128 MB
  `vosk-model-en-us-0.22-lgraph`, with ordinary/sensitive confidence defaults of
  `0.60`/`0.90` and a hard sensitive-confirmation floor of `0.80`.

## Compatibility

- Existing SQLite data and the contiguous migration chain are unchanged.
- Existing user configuration remains user-owned. Missing Version 2 settings receive
  validated defaults; invalid settings fail closed.
- The old `vosk-model-small-en-us-0.15` directory is not deleted. Model archives and
  extracted models remain ignored by Git and are not included in packages.
- Terminal, GUI, and voice input continue through the same `OmegaSession`, parser,
  dispatcher, safety gateway, history, and result lifecycle.

## Clarification safety

An application-name question is scoped to one active session, expires after 30
seconds by default, allows one reply, and clears on cancellation, timeout, shutdown,
or execution. Contextual `yes please` or `open it` creates a typed
`OPEN_APPLICATION` command; it does not execute directly. Multiple or absent matches
are never guessed.

This clarification is separate from central sensitive-action confirmation. A bare
yes/no with no current application question cannot authorize an action, and sensitive
operations still require their exact displayed confirmation phrase.

## Local setup

Install the optional voice dependencies, download the model only from the official
[Vosk model catalogue](https://alphacephei.com/vosk/models), extract it to
`data/voice_models/vosk-model-en-us-0.22-lgraph`, and enable voice in the user
configuration. Use `omega --list-audio-devices` before selecting a microphone index
or exact device name.

## Verification still required

The model archive and structure were validated and the model loaded with Vosk. Real
microphone accuracy, Indian English performance, long-running GUI behavior, and a
clean-machine executable/installer upgrade still require physical Windows testing.
No recognition-quality claim is made from automated tests.
